## 🔍 Phase 0: Source API & Entity-Driven Aggregation Analysis

### 0.1 Provider Purpose & Marketing Value Proposition
- **Domain Identity:** Shopify is the world's leading eCommerce engine. It holds the ultimate **Transactional Truth**: actual checkouts, payments, taxes, refunds, items fulfilled, and real customer accounts.
- **The Game-Changer in APIs Hub:**
  Up to now, APIs Hub has relied on **Metric Pre-Aggregations** (daily summary numbers like `cost_micros / 1000000` or `daily_impressions`).
  **Shopify unlocks Entity-Driven and Event-Driven Aggregations**:
  - We cache raw, discrete entities: **`Orders`**, **`Order Lines / Products`**, **`Customers`**, **`Discounts`**, and **`Stores`**.
  - We can answer multi-dimensional atomic business questions:
    - *What is the Net Revenue generated by Customer X over time?*
    - *Which Discount Code drove the highest Average Order Value (AOV)?*
    - *Which Product Variant has the highest refund or cancellation rate?*
    - *What is the cohort repeat purchase rate across customer lifecycles?*

### 0.2 Entity Topology & Relational Mapping in APIs Hub
Shopify maps directly to the rich entity model already established in `apis-hub`:

```
Tenant Project (APIs Hub)
  └── Asset: Shopify Store (channeled_store: shop_domain)
        ├── Customers (channeled_customers -> Customer)
        │     ├── email, phone, name, orders_count, total_spent
        │     ├── Geolocation Data: default_address (city, province/state, country_code, zip, street)
        │     └── identity_hash = MD5(LOWER(TRIM(email)))
        ├── Catalog Entities:
        │     ├── Products (channeled_products -> Product)
        │     ├── Variants / SKUs (channeled_product_variants -> ProductVariant)
        │     └── Price Rules & Discounts (channeled_discounts -> Discount)
        └── Orders (channeled_orders -> Order)
              ├── order_number, processed_at, currency
              ├── total_price, subtotal_price, total_tax, total_discounts
              ├── Geolocation / Addresses: shipping_address & billing_address (city, state, country, zip)
              ├── line_items -> ManyToMany (channeled_products, channeled_product_variants)
              ├── discounts_applied -> ManyToMany (channeled_discounts)
              └── customer -> ManyToOne (channeled_customer)
```

### 0.3 Ingestion Strategy: Dual-Track Persistence
1. **The Raw Relational Ingestion (`syncEntities` & `sync`):**
   - Ingests Orders with their nested line items and discounts into `channeled_orders`, `channeled_order_channeled_products`, and `channeled_discounts`.
   - Ingests Customers into `channeled_customers` carrying lifetime totals and `identity_hash`.
2. **The Atomic Journey Track:**
   - Ingests order events (`order_placed`, `order_cancelled`, `order_refunded`) into `channeled_events` with order totals, currency, and line items for the **Human Journey Timeline**.
3. **The Pre-Aggregated OLAP Track:**
   - Feeds the Pre-Aggregation Engine to roll up daily store performance:
     `orders_total`, `gross_revenue`, `net_revenue`, `discounts_total`, `taxes_total`, `average_order_value (AOV)`.

### 0.4 Technical Challenges for Ingestion & Caching
- **Shopify GraphQL vs REST API:**
  - Modern Shopify implementations use the **GraphQL Admin API** with **Bulk Operations** (`bulkOperationRunQuery`) for massive historical order/product dumps without hitting REST API call limits.
  - For recent/incremental syncs: REST or paginated GraphQL using `cursor`.
- **API Call Limits (Leaky Bucket):**
  - Standard Shopify stores: 40 points/sec (restore rate 2/sec); Shopify Plus: 80 points/sec.
  - Implement dynamic backoff when `extensions.cost.throttleStatus.currentlyAvailable` drops below safety threshold.
  - Set `getDefaultMaxWorkers()` to **2** (or 3 for Shopify Plus).
